# Stage API for tools

Methods on the 3D stage (`web/stage/stage.mjs`, the `Stage` instance the App keeps as `node.ssStage`) for tools that edit a scene without a mouse: ✦ Ask's actions, scripts, tests. `duplicate`, `placeInFrame`, `setRig`, `setPose` and `setExposure` are ordinary edits: on success each re-poses the stage and records one undo step (through `onChange`), like doing it by hand; a refused call changes nothing and records none. `openPhysicsPanel` only selects and opens a panel (no scene data changes), so it records no undo step, as selecting by hand records none. None of them throws for a bad argument (including `null` or a missing `where` for `placeInFrame`): they say what was wrong.

| Call | Does | Returns |
|---|---|---|
| `stage.duplicate(id)` | A copy of object `id` (person, prop, vehicle) beside it: offset along +X by its height x 0.8 (at least 1 m), with its **base** keys (`keys`, deep-copied, offset the same), so in every shot without blocking of its own it moves like the original. Its per-shot blocking (`by_shot`) is not copied, even when the active shot has some. Does not need or change the selection. | the new id, or `null` when there is no object `id` |
| `stage.placeInFrame(id, {x, y?, distance_m?})` | Puts the object's ground point at a place in the **active shot camera's** frame (the shot's keys, rig and lens at the playhead, never a live virtual-camera preview on screen), on the walkable ground: the stage floor or the set's own raised floor (a station platform), so the point lands on the third at that floor's height. A person's feet follow the floor by themselves (key height 0); a prop on a raised floor is keyed at that floor's height (`key_y` set), and `key_y` is dropped only when none of its keys in any shot is raised any more. `x`: `"left"` or `"right"` (the thirds, 1/3 and 2/3 of the width), `"center"`, or a number 0..1 (0 = left edge), also as a numeric string (`"0.3"`); a boolean, an array or an empty string is refused. Riding (`mount_id`) or carried (`carry_id`) objects are refused (place what holds them). Under a steep or top-down camera the ground distance first falls then grows up the frame (the column passes under the camera): every crossing is found and the one nearest the frame's centre line is used, so near distances work there too. `distance_m`: how far from the camera, measured along the ground. `y` (0..1, 0 = top), used when there is no `distance_m`: where that screen point meets the ground. With neither, it keeps its present distance. A one-key object moves as a whole; a keyed (moving) one gets a key at the playhead. With per-shot blocking (`by_shot`) in the active shot, that shot's keys are edited and the base `keys` / `position` stay. | `{ok: true, position: [x, y, z]}` (y: 0, or the raised floor's height for a prop) or `{ok: false, error}` (unknown id, `where` not an object, bad `x` / `y` / `distance_m`, a point above the horizon, a distance nearer than the ground the camera sees, or farther than the camera can put it: a steep or top-down camera sees ground only so far up the frame, and the error says how far). `where` omitted or `null` = `{x: "center"}` at the present distance. |
| `stage.setRig(type, amount, params)` | Puts the active shot's camera on a rig (`free`, `tripod`, `dolly`, `chapman`, `slider`, `jib`, `steadicam`, `handheld`, `drone`, `drone_fpv`); `amount` 0..2, `params` `{seed, arm, pivot}` as before. | `{ok: true, rig}` (a copy of what was set), or `{ok: false, error: "unknown rig '<type>'"}` (also for inherited names like `toString`), or `{ok: false, error}` when `params` is given and isn't a plain object (a string, number, array); nothing changes then |
| `stage.openPhysicsPanel(id?)` | Selects object `id` when given, then opens the Physics panel (`physpanel.mjs` `open()`) for the selection. The App hands its panel to the stage as `stage.physicsPanel`. | `{ok: true, id}` (the selected id), or `{ok: false, error}` (unknown id, no panel, or `{ok: false, error: "select something"}` with no id and nothing selected: no empty panel is opened) |
| `stage.setCameraCurve(mode)` | The active shot's camera curve: `"smooth"` (curve version 2, [camcurve.mjs](camcurve.mjs): no speed jumps at keys, focal in log space), `"even"` (version 2 at one even speed by arc length, camera and target travel combined; interior key times and holds are ignored) or `"legacy"` (the old curve shots saved before version 2 play). One undo step. `stage.cameraCurve()` reads it. | `{ok: true, curve}` or `{ok: false, error}` |
| `stage.setPose(id, pose, opts?)` | Sits or stands a person (man, woman, child). `pose`: `"sit"` on a seat: `opts.on` = the seat's id, else the nearest chair, bench, sofa, armchair, stool, rock, table or cube within 1.5 m (ground distance) of where they are at the playhead; the seat height comes from the prop (humans.mjs `MOUNTS`: chair 0.47 m, bench 0.47, sofa 0.54, armchair 0.44, scaled by the prop's `scale` and its `height_m` against the library height; a named static custom prop: 0.6 x its height). It is the same mount as dropping them on the seat (`mount_id`, `pose: "sit"`). `"sit_floor"`: down on the floor where they are (`pose: "sit_floor"`, hips 0.10 m up, knees up); from a seat, they get off first and sit 0.6 m in front of it. `"stand"`: up again (off the seat, as `unmount`; or up from the floor). The lifelike body follows in both (people/avatars.mjs `sitBody`): it is not sent to the clay. A keyed (moving) person sitting on the floor slides along their keys seated: key them still. One undo step when something changes. | `{ok: true, pose, on?: seatId, changed}` (`changed: false` = already so, no undo step), or `{ok: false, error}` with nothing changed: unknown id, `'<name>' is not a person`, `unknown pose '<p>' (sit, sit_floor or stand)`, `opts must be an object like {on}`, `'<name>' is being carried`, `no object '<on>'`, `can't sit on '<name>' (...)` (a car, horse, bike, boat, a person, a non-seat prop such as a crate), `nothing to sit on within 1.5 m of '<name>': pass {on: id}, or use 'sit_floor'` |
| `stage.setExposure(stops)` | "Lights down": the scene dimmer, in photographic stops, `-6`..`+2` (`-1` = half the light, `0` = as lit; `EXPOSURE_MIN` / `EXPOSURE_MAX` exported). Every light in the set (sun, sky fill, film lights, practicals, headlights, fire) and a plain-colour sky are scaled by 2^stops while the viewport and every capture render, then put back; emissive surfaces (neon, screens) keep their glow. Saved in the scene as `lighting.exposure_stops` (absent at 0); the prompt's lighting line says "lights dimmed down, low-key exposure" (-1 or lower), "lights down very low" (-3 or lower) or "lights up bright" (+1 or higher). Numbers or numeric strings (`"-1.5"`), rounded to 0.01. One undo step when it changes. `stage.exposure()` reads it (a number, 0 when unset). | `{ok: true, stops, changed}` (`changed: false` = it was already that, no undo step), or `{ok: false, error}` with nothing changed: `stops must be a number (got '<x>')` (null, booleans, arrays, `""`, NaN, Infinity) or `stops must be between -6 and 2 (got <n>)` |

Tested in [tests/js/avatars_m15.test.mjs](../../tests/js/avatars_m15.test.mjs) ("Stage API for tools"): `placeInFrame` against a known camera (the projected point lands on the third at the asked distance, within 2 mm), a straight-down camera refusing 10 m, and `null`; `openPhysicsPanel` recording no undo step ("round 2" tests); `placeInFrame` with a preview camera on screen and with per-shot blocking, `setRig` with bad `params` and inherited names, `duplicate` of a person with per-shot blocking ("round 3" tests).

More in [tests/js/people_m16.test.mjs](../../tests/js/people_m16.test.mjs): near distances under a top-down and a steep camera, numeric strings and refused booleans / arrays, riding or carried objects refused, a raised platform floor (the point lands on the third at the platform's height; `key_y` kept for another shot's raised keys), and `openPhysicsPanel()` with nothing selected.

**Play is read-only.** Playing a shot (the App's Play button: `stage.setFrame(f)` every tick), scrubbing and the key strip (`keyInfo()`) never write `shot.camera_keys`: they read the keys through `_camKeysView()`, and a shot with no keys yet plays from the scene's camera without a key being stored. The flat `camera_keys` field stays a mirror of the active shot's own array (the same array, never a copy; older readers such as `soundstage/look/scene.py` read it), as before. Editing (`_camKeys()`: a key at the playhead, a rig, a preset) still creates the first key. Tested in [tests/js/askhooks_play.test.mjs](../../tests/js/askhooks_play.test.mjs).

## Ask's host hooks (web/soundstage.js `mountAsk` host, helpers in web/hosthooks.mjs)

| Hook | Does | Returns |
|---|---|---|
| `host.project()` | The open project, read now from its saved `project.json` through `window.__ssProject.project()` (web/project/projectbar.mjs). Async. Never throws. | a Promise of `{name, id}`: `id` is `"p_" + 8 hex` only when confirmed against the saved project.json, else `null` (not saved yet, saved before ids existed, a copy, a renamed or reused name); `name` the project's (or the tab's) name, or `null`. With no project controller, or a failed read: the controller's sync answer (`projectId()`, `current().name`), else `{name: null, id: null}` |
| `host.cut.panel()` | The live `CutPanel` instance (web/cut/cut.mjs), the very object the Cut view uses, so its own methods can be called (and its edits go through its own Undo). | the panel, or `null` when the Cut's view is not in the page |
| `host.lights` | `{get(), set(stops), down(stops = 1), reset()}` on `stage.setExposure`: `down(n)` dims n stops more from where it is (n >= 0), `reset()` back to 0. | `get()`: a number; the others: what `setExposure` returns; `down` with a negative or non-number n: `{ok: false, error: "stops must be a number >= 0 (got '<n>')"}` |
| `host.stage.setPose(id, pose, opts)` | `stage.setPose` (above). | as `stage.setPose` |

The Ask model server (`soundstage/assistant.py`, `GET /soundstage/assistant/status`) also says `local: true` when the model server's URL is this machine (a loopback address: `127.x.x.x`, `::1`, `localhost`, `0.0.0.0`, or this machine's own host name; never resolved through DNS) and `false` for any other host. `POST /soundstage/assistant/chat` sizes Ollama's `num_ctx` to the request: its messages' length / 3.5 tokens + the reply room (`options.num_predict`, else 2048), at least the request's own `options.num_ctx`, rounded up to a multiple of 4096, never below Ollama's default 4096 and never above `SOUNDSTAGE_ASSISTANT_MAX_CTX` (default 32768): a ~3,500-token planner prompt gets 8192. Tested in tests/test_assistant.py.

Hooks tested in [tests/js/askhooks_host.test.mjs](../../tests/js/askhooks_host.test.mjs), [askhooks_lights.test.mjs](../../tests/js/askhooks_lights.test.mjs) and [askhooks_sit.test.mjs](../../tests/js/askhooks_sit.test.mjs) (the real Rocketbox man sitting on a chair and on the floor, when the bodies are installed).
